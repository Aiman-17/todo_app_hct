# Kafka Event Contracts: `todo.tasks.*`

**Purpose**: Defines the schema and semantics for all task lifecycle events published by the backend via Dapr pub/sub. Any consumer (Phase 5 or beyond) MUST accept messages conforming to these schemas.

**Naming convention**: `todo.<domain>.<event-type>` (per constitution Principle VI)

---

## Topic: `todo.tasks.created`

**Published when**: A new task is successfully persisted in the database (via MCP `add_task` tool).

```json
{
  "specversion": "1.0",
  "type": "todo.tasks.created",
  "source": "todo-backend",
  "id": "<uuid>",
  "time": "2026-02-03T12:00:00Z",
  "datacontenttype": "application/json",
  "data": {
    "task_id": 42,
    "title": "Buy groceries",
    "description": "",
    "priority": "medium",
    "user_id": "user-abc-123",
    "created_at": "2026-02-03T12:00:00Z"
  }
}
```

## Common Rules

- All events follow the [CloudEvents spec v1.0](https://github.com/cloudevents/spec/blob/v1.0.2/cloudevents/spec.md).
- `id` is a UUID generated by the backend at publish time.
- `time` is UTC ISO-8601.
- `source` is always `todo-backend` for Phase 4.
- Event publishing is **best-effort** in Phase 4: if the Kafka broker is unreachable, the task operation still succeeds and a warning is logged. No event is lost permanently — retries are handled by Dapr's built-in retry policy.
- `user_id` is included for downstream consumer filtering (user isolation).
